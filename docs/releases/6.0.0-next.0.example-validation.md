## Migration performed

These standard Angular commands were run in the copy. No peer-dependency bypass flags were used:

```sh
npm ci --ignore-scripts --no-audit
./node_modules/.bin/ng update \
  @angular/core@15.2.10 @angular/cli@15.2.11 @angular/material@15.2.9 \
  ng-mat-select-infinite-scroll@6.0.0-next.0 rxjs@7.8.2 --allow-dirty
./node_modules/.bin/ng generate @angular/material:mdc-migration \
  --components=all --directory=src --interactive=false
npm run build -- --configuration production
```

Material's initial update preserved legacy component imports. Its MDC migration restored the standard `MatSelectModule` and `MatFormFieldModule` imports needed for this integration. Angular CLI updated the TypeScript target and class-field setting. The resulting component controller, module, CSS, and template match the original source, except for one read-only `data-test-offset` template binding used by the tests.

## Browser results

Two one-off tests using the standard Playwright 1.65.1 test runner passed, with zero failures or flaky results:

- Load all 100 options in order without duplicates, preserve the viewport during append, stop at completion, select Option 99, and retain that selection after reopening.
- Scroll and close before the debounce expires: no extra page is loaded. Reopening and scrolling loads the next page normally.

A subsequent clean `npm ci --ignore-scripts --no-audit` and production rebuild also passed, producing the same application build hash (`91b5516a14655af8`). Both `legacy-peer-deps` and `force` were false.

Both cases reported no page errors. The screenshot was visually inspected. These are validation tests authored for the copy, not the example repository's existing unit-test suite.

The installed package's version, registry URL, and SHA-512 integrity match [the published beta record](6.0.0-next.0.validation.json). The implementation fingerprint is `8779dbc3851fe3db544e33d706fa6ff00e5ddd53e9fc27cb4979d927417d0545`.
